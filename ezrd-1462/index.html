Corrections vs. the 2026-05-12 plan
  • "ESO auto-surfaces every payload key as a pod env var." False. The chart's ezrouting.externalSecretsEnv helper uses per-key secretKeyRef — not envFrom: secretRef. ESO populates the K8s Secret with every JSON field, but only keys enumerated in _helpers.tpl reach the pod. Wired in ezrd-gitops PR #188.
  • "Add an IRSA grant for crons-worker." The crons-worker pod has no IRSA. serviceAccount.create: false in the ezrouting chart; an ezrd-app-role IRSA module exists in ezrd-infra/terraform/modules/iam but isn't attached to any SA. The active path is the static ezrd-app-<env> IAM user (provisioned by s3-ezrouting) which already has s3:PutObject on the whole ezrd-<env>-ezrouting bucket. Routing PR #1477 passes those creds explicitly to new S3Client(...) for shadow mode — no IRSA wiring needed.

Pod env vars
○ Optional

Tuning knobs (not secrets)

Plain Helm values under envFromValues in the env overlay. Materialized as pod env vars by the chart's ezrouting.externalSecretsEnv helper, which iterates the map alphabetically.

EXPORT_STUDENT_BUSES_CONCURRENCY DEFAULT: 3 ○ Optional

Override worker concurrency. Bump to 4–5 if back-to-school surge pushes the 30-min window; drop to 2 if pod memory is tight. Resolution order: env var → configuration.cronJobConcurrency.exportStudentBuses → default. No code change required.

EXPORT_STUDENT_BUSES_SHADOW_PATH DEV: s3://ezrd-dev-ezrouting/export-student-buses-shadow/ ⚑ Wired in PR #188

Validation-phase only. When set, the worker's maybeAttachShadowExec diverts all uploads to S3 instead of real SFTP. Object lands at <bucket>/<prefix>/<entryName>/<filename>. Accepts a full s3://bucket/prefix URL or a bare prefix (then needs the bucket var below). Dev uses the existing app bucket — the static ezrd-app-dev IAM user already has s3:PutObject on the whole bucket, so no IAM work is required.

EXPORT_STUDENT_BUSES_SHADOW_BUCKET DEFAULT: unset ○ Optional

Required only if SHADOW_PATH is a bare prefix (not a full s3:// URL). Ignored when SHADOW_PATH is unset or already carries an s3:// scheme. Dev uses the full-URL form so this var stays unset.

Already in place — don't re-do

ExternalSecret → K8s Secret

ezrd-gitops/charts/ezrouting/templates/externalsecret.yaml uses dataFrom.extract against ezrd/<env>/ezrouting. Every JSON field lands in the materialized K8s Secret automatically. But reaching the pod env still requires a secretKeyRef entry in _helpers.tpl (PR #188).

Managed SFTP creds (192/201)

configuration.sftp in config.json already holds creds for sftp.ezrouting.com. No Secrets Manager work for managed-mode entries.

Redis (BullMQ)

cron-jobs/redis-connection.js reuses the existing connection used by every other cron module. Nothing new.

S3 IAM for shadow mode

ezrd-app-<env> static IAM user has s3:PutObject on ezrd-<env>-ezrouting/*. Worker passes those creds explicitly via configuration.aws (Routing PR #1477).

Datadog logs/metrics

app/datadog/index helpers already used by every cron module. Just verify dashboards pick up the new queue name.

Dry-run password redaction

makeDryRunExec runs every command through redactSshpassPassword() before logging. sshpass -p <value> (double-quoted, single-quoted, unquoted) is replaced with ***REDACTED***.
