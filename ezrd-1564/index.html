EZRD-1564 — busapp Validate-First · Test Steps

Confirm POST /api/v1/mobile/busapp rejects bad payloads with an immediate 400 (before any downstream call) instead of burning the full ~138s timeout. Valid payloads still proxy through. API test — no UI.

UAT targets

  • • Endpoint: POST https://core.ezd-uat.runpathwise.com/api/v1/mobile/busapp
  • • Health: GET https://core.ezd-uat.runpathwise.com/health
  • • Login (for token): POST https://ezr-uat.runpathwise.com/login/busapp
  • • Client: mwm

The validation tests require a SD360 driver token. Without it the endpoint rejects before validation, so those cases are skipped. Health checks need no auth.

1 · Get a driver token

POST to login with SD360 driver creds (username/password or a <tenant>;<code> QR string). Copy token from the response.

curl -s https://ezr-uat.runpathwise.com/login/busapp \
  -H 'Content-Type: application/json' \
  -H 'mobile: 363DC37D-2509-4E65-8D6A-F5C155DEBDD8' \
  -H 'app: busapp' \
  -d '{"username":"<sd360-driver>","password":"<password>"}'
Expect: 200 with a JSON token. Use it as <TOKEN> below.

2 · Run the suite (Bruno — fastest)

Collection: ezrd-api-tests#65, folder ezd-core/.

cd ezrd-api-tests/ezd-core
bru run . --env mwm-uat \
  --env-var 'username=<sd360-driver>' \
  --env-var 'password=<password>'
# or, instead of username/password:  --env-var 'qrcode=<tenant>;<code>'
Expect: all 12 cases (C_1564_1–12) pass. Without creds, the 2 health checks pass and the validation cases skip (don't fail).

3 · What each case sends & expects

Each request goes to POST …/api/v1/mobile/busapp with headers client: mwm, app: busapp, mobile: 363DC37D-…, token: <TOKEN>. Body varies:

CaseBody sentExpect
1–2 HealthGET /health (no auth)200, body {status:'ok'}
3–4 Bad method{"method":"INVALID_METHOD","url":"/api/routes/mine","headers":{...},"data":{}}400 B2E5D741, returned immediately
5–6 Bad URL{"method":"GET","url":"/routes/mine",...} (no /api/ prefix)400 B2E5D742, immediately
7–8 Null headers{"method":"GET","url":"/api/routes/mine","headers":null,"data":{}}400 B2E5D743, immediately
9–10 Empty body{}400 (no method → B2E5D741), immediately
11–12 Valid{"method":"GET","url":"/api/routes/mine","headers":{"token":"<TOKEN>"},"data":{}}Not 400 from validator and not 5xx — passes validation, proxies to ezrouting
Key result (the fix): every invalid case returns 400 right away (well under the old ~138s timeout). Before the fix these hung for the full downstream timeout before failing.

4 · Manual spot-check (curl)

Bad method — should come back instantly with a 400:

curl -s -w '\n%{http_code}  %{time_total}s\n' \
  https://core.ezd-uat.runpathwise.com/api/v1/mobile/busapp \
  -H 'Content-Type: application/json' -H 'client: mwm' \
  -H 'app: busapp' -H 'mobile: 363DC37D-2509-4E65-8D6A-F5C155DEBDD8' \
  -H 'token: <TOKEN>' \
  -d '{"method":"INVALID_METHOD","url":"/api/routes/mine","headers":{"token":"<TOKEN>"},"data":{}}'
Expect: {"errcode":"B2E5D741","message":"Invalid method"}, HTTP 400, time_total a fraction of a second (not ~138s).
