EZRD-1564 — busapp Validate-First · Test Steps

Confirm POST /api/v1/mobile/busapp rejects bad payloads with an immediate 400 (before any downstream call) instead of burning the full ~138s timeout. Valid payloads still proxy through. API test — no UI. Env: prd-UAT, tenant testqa.

Hosts (prd-UAT)

  • • ezd-core API (the fix is here): https://core.ezd-uat.runpathwise.com  (EKS — the variant the Argo ApplicationSet deploys)
  • • Endpoint: POST /api/v1/mobile/busapp
  • • Health: GET https://core.ezd-uat.runpathwise.com/health
  • • Login (driver token): POST https://uat.pathwiserouting.com/login/busapp
  • • Tenant / client: testqa

Legacy fallback: if this env is still served by the EC2 fleet (there was a cutover + rollback), use https://core.ezd-uat-ec2.runpathwise.com instead. The definitive source is the SD360 build's BASE_URL (in SafeDriver360/.env).

Auth — read this first

ezd-core gates /api/v1/mobile/busapp with a server token, not the driver login token. There are two distinct credentials:

  • • ezd-core server token — sent in the token request header. This is what gets you past ezd-core's auth gate. It's the EZRD_SERVER_TOKENS_MOBILE secret (ESO/Secrets Manager) for the env. Without it → 401 before validation runs.
  • • Driver login token — goes in the request body under headers.token; ezd-core forwards it to the downstream ezrouting. Only needed for the "valid payload" case to proxy through.
Heads-up on the Bruno collection: as written it puts the driver login token in the token header — that returns 401 at ezd-core's gate and never reaches the validation. Set the token header / env var to the server token for cases 3–12 to actually run. (Verified: a driver JWT and the mobile UUID both 401.)

1 · Get the credentials

Server token (required for all busapp cases): pull EZRD_SERVER_TOKENS_MOBILE for the env from Secrets Manager / ESO. Call it <SVRTOK>.

Driver login token (only for the valid-proxy case): log in with SD360 driver creds — copy token from the response, call it <DRVTOK>:

curl -s https://uat.pathwiserouting.com/login/busapp \
  -H 'Content-Type: application/json' \
  -H 'mobile: 363DC37D-2509-4E65-8D6A-F5C155DEBDD8' \
  -H 'app: busapp' \
  -d '{"username":"<sd360-driver>","password":"<password>"}'
Expect: 200 with a JSON token. (For testqa the driver user is testqadriverpathwise@yopmail.com.)

2 · Run the suite (Bruno)

Collection: ezrd-api-tests#65, folder ezd-core/. Override the host + set token to the server token:

cd ezrd-api-tests/ezd-core
bru run . --env mwm-uat \
  --env-var 'coreHost=https://core.ezd-uat.runpathwise.com' \
  --env-var 'loginHost=https://uat.pathwiserouting.com' \
  --env-var 'client=testqa' \
  --env-var 'token=<SVRTOK>'
Expect: health 2/2 pass; cases 3–12 pass. (If token is a driver login token instead, the validation cases 401 — see the auth note.)

3 · What each case sends & expects

Each request: POST https://core.ezd-uat.runpathwise.com/api/v1/mobile/busapp, headers client: testqa, app: busapp, mobile: 363DC37D-…, token: <SVRTOK>. Body varies:

CaseBody sentExpect
1–2 HealthGET /health (no auth)200, body {status:'ok'}
3–4 Bad method{"method":"INVALID_METHOD","url":"/api/routes/mine","headers":{},"data":{}}400 B2E5D741, returned immediately
5–6 Bad URL{"method":"GET","url":"/routes/mine",...} (no /api/ prefix)400 B2E5D742, immediately
7–8 Null headers{"method":"GET","url":"/api/routes/mine","headers":null,"data":{}}400 B2E5D743, immediately
9–10 Empty body{}400 (no method → B2E5D741), immediately
11–12 Valid{"method":"GET","url":"/api/routes/mine","headers":{"token":"<DRVTOK>"},"data":{}}Not 400 from validator and not 5xx — passes validation, proxies to ezrouting
Key result (the fix): every invalid case returns 400 right away (well under the old ~138s timeout). Before the fix these hung for the full downstream timeout before failing.

4 · Manual spot-check (curl)

Bad method — should come back instantly with a 400:

curl -s -w '\n%{http_code}  %{time_total}s\n' \
  https://core.ezd-uat.runpathwise.com/api/v1/mobile/busapp \
  -H 'Content-Type: application/json' -H 'client: testqa' \
  -H 'app: busapp' -H 'mobile: 363DC37D-2509-4E65-8D6A-F5C155DEBDD8' \
  -H 'token: <SVRTOK>' \
  -d '{"method":"INVALID_METHOD","url":"/api/routes/mine","headers":{},"data":{}}'
Expect: {"errcode":"B2E5D741","message":"Invalid method"}, HTTP 400, time_total a fraction of a second (not ~138s). (Wrong/absent server token → 401 Unauthorized before validation.)
