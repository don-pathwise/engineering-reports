What this ticket is asking for

A transportation coordinator wants to bulk-set the "Exempt from Eligibility Recalculation" flag on students through the student CSV import, instead of toggling it one student at a time. The field already exists on the individual student record (added in EZRD-1657) and there was a one-off backend script for a single district (EZRD-2006); this story is the permanent, self-service version wired into the normal import.

Key implementation fact

"Exempt from Eligibility Recalculation" is not a column on the student table. It is the API/model field exemptFromEligibilityRecalc, physically stored as the locked column in ed_eligibilitystudent (the row with categoryId = 0) — internally the "rider-lock". All writes go through the shared @transactcomm/eligibility-lock package (setRiderLock). So the import cannot just set a field on the student object; it must make a second, dual write into the eligibility domain after the student is saved.

Acceptance criteria

  • Column is available as a mappable column in the student CSV import.
  • Present & true → flag checked on the matching student after import.
  • Present & false → flag unchecked after import.
  • Absent from the file → existing value preserved; no data overwritten.
  • Post-import behaves identically to a manual toggle — recalc respects the flag.
  • Import validation surfaces a clear error for an unrecognized value.

Implementation plan

Two decisions to confirm first (ticket's open questions)

  1. Accepted boolean tokens. Recommend: true = true/t/yes/y/1, false = false/f/no/n/0 (case-insensitive); empty cell = leave that student's flag unchanged; anything else = validation error. This is a superset of the existing parseBoolean (which accepts y/t/yes/true) plus explicit false + 1/0 (common in CSV exports).
  2. Module gating. Recommend: only expose the column when settings.eligibilityEnabled is on, matching EZRD-1657's treatment of the field. Non-eligibility tenants never see it and no stray ed_eligibilitystudent rows get created.

Ordered steps

  1. Verify broken state (pre-implementation). In a running environment on the base branch, open the student CSV import for an eligibility-enabled tenant and confirm there is no "Exempt from Eligibility Recalculation" mappable column. Screenshot as the baseline.
  2. BE — add rider-lock dual write to the import save path (app/import/import-student.js). Instantiate eligLock via createEligibilityLock({...}) exactly as app/student/api.js does (knexModel primary/replica pool + shared.timestamp). In save(), after the student is created/updated, when !context.sandboxId and typeof student.exemptFromEligibilityRecalc === 'boolean', call eligLock.setRiderLock(context, { studentId: student.id, semesterId: context.semesterId || 0, locked: student.exemptFromEligibilityRecalc }) — best-effort (try/catch → datadog.logEzrWarn, never fail the student save), and write a best-effort per-student audit.log only when changed. Undefined ⇒ skipped ⇒ preserved (the absent-column AC).
  3. FE — recognize the column (ui/src/settings/import/import.student.js). Add 'Exempt from Eligibility Recalculation' to baseFields, gated on eligibilityEnabled (inject the settings model; add the field in attached() so it also flows into dataFields/auto-map). In createStudentRecord(), set result.exemptFromEligibilityRecalc from a new strict parse: mapped + recognized ⇒ true/false; mapped + empty ⇒ undefined (preserve that row); mapped + unrecognized ⇒ mark invalid; unmapped ⇒ undefined.

  5. FE — strict parse helper (ui/src/settings/import/import.common.js). Add a helper returning true | false | undefined | INVALID per decision 1, reusing the existing token style. Leave the lenient parseBoolean untouched (other columns depend on it).
  6. Tests (TDD, backend). New test/unit/import/import-student.spec.js mirroring import-vehicle.spec.js: mock @transactcomm/eligibility-lock + student module; assert (a) true ⇒ setRiderLock locked:true, (b) false ⇒ locked:false, (c) undefined ⇒ setRiderLock not called, (d) sandbox context ⇒ not called, (e) setRiderLock throw ⇒ student save still succeeds (error === null).
