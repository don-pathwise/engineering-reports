Inside the cron run

The CLI tool runs in three substeps. Nothing is written to the database — this is read-only transformation.

a

Build records

Loop every active student. Join in contacts, schools, bus assignments, routes, stops, agendas, UDFs.

b

Map to columns

Apply the district's --fields and --headers. Inline JS lambdas are eval'd per row.

s => s.agenda.homeToSchool ? 'To' : 'From'
c

Serialize & write

Write to local /tmp. CSV by default, --tab for TSV, --xlsx for Excel.

SCP to central drop host

Lands in a per-district folder on sftp.ezrouting.com. The folder name is the client name + a random hash.

+ optional second leg

If the tenant has sftpSettings in its DB, the file is also pushed via SFTP using the client name as the username on the same host.

4
Landing

Where the file ends up

Depending on the path taken in step 3, the file rests in one of two places.

External path

On the customer's own server

File is now sitting on infrastructure owned and operated by the district (or their SaaS vendor — Beacon, ParentLink, etc.). We have no further visibility once the upload completes.

Managed path

In a per-district folder

sftp.ezrouting.com:<path>/<client>-<hash>/

Waiting for the district to SFTP in and pull it. The district has an SFTP user account on this host; they connect into their own home dir.

5

District's SIS ingests the file

Whether the file arrived via push or sat waiting to be pulled, the consumer is the same: the district's source-of-truth system reads it on its own schedule.

What changes when this moves to EKS

The data flow itself doesn't change — the CLI tool's behavior is preserved end-to-end. Only the runner moves: from crond on aarzhou's EC2 box to the crons-worker pod under bullmq_crons on EKS. Three things have to follow it:

1 · Network

Outbound reachability

EKS pod's NAT egress must reach sftp.ezrouting.com, all 7 external SFTP hosts (some non-standard ports), and the private IP for stfrancismn.

2 · Allowlisting

Customer IP whitelist

Districts currently allow the EC2's external IP. Every external destination needs the new EKS NAT IP added before cutover, or uploads silently fail.

3 · Secrets

Credential migration

Plaintext SFTP passwords (inline in the launcher today) and the system SFTP credentials (in config.json) move to AWS Secrets Manager.
