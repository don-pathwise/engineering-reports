Verification guide · EZRD-1653

Splitting a trip added stops nobody assigned

Two runs of the same steps. On production you should still see the bug — extra stops on the receiving buses that nobody assigned to them. On UAT, with the fix deployed, the same split should come out clean.

App · Trip Preparation Tenant · testqa Flow · View/Edit Trip → Break Up Two runs · prod, then UAT
Orientation

What you're doing, in plain terms

Trip Preparation is the “today isn't going to plan” tool. When a bus loses its driver, a dispatcher covers its stops using other buses — often by splitting one trip's stops across two other buses. That's the action you're going to perform, and it's what the reporting district was doing when they hit this.

Trip Prep edits apply to one service day and don't change the permanent route plan — which is why moved stops are labelled “Moved from route …” and carry an undo arrow.

The bug

Each receiving bus gained extra stops with no “Moved from” label — typically a school the bus doesn't serve, dragged in because a student's pickup got separated from it. Those stops reached the driver tablets and parent apps, so a bus showed a longer route with times that didn't match.

The fix

Those stops were scratch work from the arrival-time calculation, never meant to be saved. They're now discarded before the split is stored, so the bus keeps only the stops it was actually given.

Two things to know before step 1

The route list is split across two tabs — UNCOVERED ROUTES (the one you land on) and COVERED ROUTES. A route lands on COVERED only when it has both a bus and an available driver, so the same route can be on a different tab in each environment. The “Which tab” column in each lineup table below is the one to follow — it was read from that environment's own data.

Inside a trip, the stop list is numbered in a # column. You never have to hand-count stops — scroll to the bottom and read the number on the last row.

  1. 1
    Set the service day

    Click the date at the top of the page, step back with < to the right month, then click the day. Wait for the route counts to appear on the two tabs.

  2. 2
    Record both destinations' baselines

    For each destination trip: hover its route row, click the ✏️ beside the trip name, scroll to the bottom of the stop list and write down the number on the last row. Also note the trip's time window from the route list. Then CANCEL. Everything after this compares against these two numbers, so don't skip it.

  3. 3
    Open the source trip and click BREAK UP

    Find West Elementary, hover the row, click the ✏️ beside Test3. The pencil only exists while the row is hovered. In the trip window, click BREAK UP.

  4. 4
    Tick the two destination trips, then CALCULATE

    This list is not alphabetical and is longer than the day's route list — scroll to find each one by trip name. A ticked row turns green. Use only the two trips named above (see the traps below). CALCULATE stays greyed out until something is ticked.

  5. 5
    Click CALCULATE DETAILS

    Leave the two checkboxes at the top right (“Never move the stops to the beginning…”, “Keep original school arrival time”) unticked. This screen shows one destination at a time — use the “Select a trip to view details” dropdown to look at the other. Its row count is higher than what gets saved in both environments, so don't judge the result from here.

  6. 6
    Save: SAVE → YES → NO

    “Do you really want to save the break-up results?” → YES. Then “Do you want to send notifications to the parents…?” → NO, so no messages go out. The save has already happened by the time that second question appears.

  7. 7
    Reopen each destination and read the last row

    Back on the route list both destination time windows should now end visibly later than the baseline — a quick confirmation the split landed. Then open each destination trip again for the check below.

What you'll see — bug present

In each reopened destination trip, the DESCRIPTION column tells you where every row came from. A stop moved by your split reads “Moved from route West Elementary” with the date under it. A stop the bus already served has a blank Description. Those are the only two legitimate cases.

The bug adds rows that are neither — blank Description, but not a stop this bus served before you started. They're often a school the bus doesn't normally serve.

The test: count the rows with a blank Description

That count must equal the baseline number you wrote down in step 2. On production it will be higher — those extras are the defect. Do this on both destinations.

Decide from the saved trip, not from Calculate Details

The Calculate Details screen lists working stops in both environments, so it cannot tell them apart. Judge the result only from the reopened trip after saving — that's what the driver tablets and parent apps read, and it's the only thing this fix changes.

Before you start

Three things that will waste your time

Use the destination trips named above, not others

The Break Up list offers trips whose route isn't in the day's route list behind the modal, and picking one crashes on CALCULATE with nothing on screen to explain it. That's a separate known defect. If you do substitute a destination, first check its route name is visible in the list behind the modal. Both trips named above were confirmed present on their stated date.

The edit pencil only exists while the row is hovered

Hover the route row first. On a narrow window it sits past the right edge — widen the window or scroll the table sideways.

An empty route list means the wrong date

Trip Prep is day-scoped, and the two environments need different dates — 08/05/2026 on production, 05/27/2026 on UAT. An empty list is almost always a date outside the semester holding the data.

Afterwards

What you leave behind

Both tenants had no prior day-changes on these trips, so everything you see afterwards is yours. A saved split affects only the service day you chose and leaves the permanent route plan untouched.

If you repeat a run, start from a different source trip. Re-running a split over trips you've already split adds to the mess rather than resetting it — on the unfixed environment that makes the symptom worse each time, which is exactly what the reporting district experienced.
